# Ozon MCP

[MCP](https://modelcontextprotocol.io/)-сервер для **личного кабинета покупателя**
[ozon.ru](https://www.ozon.ru/). Даёт языковой модели доступ к заказам, истории
покупок, корзине, избранному, подборкам и вишлистам, карточкам товаров
(варианты, фото, отзывы, описания, характеристики), поиску по каталогу с
фильтрами, а также к балансу Ozon Карты и баллам — через внутренний
`composer-api`.

> В отличие от парсеров, которые умеют только анонимный каталог, этот сервер
> работает **под вашей авторизованной сессией**: он читает личные данные
> (заказы, покупки, корзину, баланс) и — если это явно включено — меняет
> корзину и избранное.

## Как это работает

Антибот Variti блокирует не-браузерные клиенты, поэтому сессия **один раз**
поднимается через настоящий headed-Chromium под Xvfb: он проходит проверку, а
из него забираются cookies и набор client-hint заголовков. Дальше все чтения и
записи идут обычным HTTP через
[`curl_cffi`](https://github.com/lexiforest/curl_cffi) (имперсонация TLS-отпечатка
Chrome) — браузер на каждый вызов больше не нужен. Он остаётся только для
обновления токенов и нескольких чтений, которые Ozon рисует на клиенте.

Требования: запуск с **российского IP** (Ozon режет датацентры и VPN) и
постоянный профиль браузера, засеянный одним живым входом.

`OZON_ENABLE_WRITES=1`.

## Сессия и стейт

Сессия живёт в **постоянном профиле Chromium**, а не в снапшоте куки. Это
осознанно: OzonID — realm, который защищает оформление заказа, — держит свою
сессию вне куки и localStorage, поэтому снапшот `storage_state` молча её теряет,
и оформление откатывается к экрану входа. Настоящий каталог профиля сохраняет
всё, поэтому одного входа хватает, а дальше сервер работает без человека.

Сам вход (email/телефон + одноразовый код) — **разовая ручная процедура**,
выполняется один раз против каталога профиля.

**`/data` обязан быть бинд-маунтом.** Там лежит профиль, а Ozon постоянно
ротирует сессию: куки, обновившиеся на HTTP-стороне, дописываются обратно в
профиль, чтобы refresh-цепочка пережила рестарт. На эфемерном каталоге вход
теряется при каждом пересоздании контейнера.

```bash
-v /opt/ozon-mcp:/data
```

В `/data` лежат `profile/` (сессия) и `price_history.json` (снимки цен
избранного). Старый `state.json`, если он есть, импортируется один раз для
засева нового профиля — этого достаточно для чтения, но не для оформления.

> **Профиль — это credential.** Он даёт полный доступ к аккаунту: заказы,
> адреса, баланс карты и оформление заказа. В git не коммитить, бэкапить только
> шифрованно.

**Две вещи, на которых легко обжечься** — обе проверены на себе:

- **Refresh-токены одноразовые.** Восстановление более старой копии сессии не
  срабатывает и даёт анонимную сессию, так что старый бэкап это не откат.
- **Заход в форму входа на оформлении понижает сессию до гостевой.** Сервер
  отказывается сохранять такое состояние, чтобы не затереть им рабочий вход.

## Настройка

| Переменная | По умолчанию | Что задаёт |
|---|---|---|
| `OZON_PROFILE_DIR` | `/data/profile` | Постоянный профиль Chromium с сессией |
| `OZON_STATE` | `/data/state.json` | Старый снапшот, импортируется один раз для засева профиля |
| `OZON_IMPERSONATE` | `chrome124` | Профиль TLS-имперсонации curl_cffi |
| `OZON_ENABLE_WRITES` | `0` | Разрешить изменение корзины/избранного/подборок |
| `OZON_ENABLE_ORDERS` | `0` | Разрешить `place_order` — **тратит деньги**, отдельный флаг |
| `OZON_MONITOR_STORE` | `/data/price_history.json` | Файл истории цен избранного |
| `OZON_TRANSPORT` | `stdio` | `stdio` (клиент сам запускает процесс) или `sse` (HTTP-сервис) |
| `OZON_HOST` | `0.0.0.0` | Адрес привязки для транспорта `sse` |
| `OZON_PORT` | `8084` | Порт, отдающий `/sse` и `/metrics` |

См. `env.example`.

## Транспорты и метрики

`stdio` — по умолчанию, подходит клиенту, который сам поднимает сервер. `sse`
запускает его как долгоживущий HTTP-сервис (так подключается удалённый агент),
и на том же порту отдаются Prometheus-метрики на `/metrics`: исходы и латентность
запросов к Ozon, повторные прохождения антибота, состояние браузера.

## Запуск

Docker (headed-Chromium и Xvfb уже внутри образа):

```bash
docker build -t ozon-mcp .

# stdio: клиент подключается к stdin/stdout контейнера
docker run -i --rm --shm-size=1g -v /opt/ozon-mcp:/data ozon-mcp

# sse: долгоживущий HTTP-сервис на :8084 (/sse + /metrics)
docker run -d --name ozon-mcp --shm-size=1g -v /opt/ozon-mcp:/data \
  -e OZON_TRANSPORT=sse -p 8084:8084 ozon-mcp
```

`--shm-size=1g` не опция: на дефолтных 64 МБ разделяемой памяти Chromium падает.

Локально через [uv](https://docs.astral.sh/uv/):

```bash
uv sync
uv run playwright install --with-deps chromium
uv run python -m ozon_mcp   # для бутстрапа нужен дисплей или Xvfb
```

## Ограничения

- **Нужен российский IP** — Ozon режет датацентры и VPN.
- **Нужен настоящий Chromium** для бутстрапа: headless детектируется.
- **Профиль требует одного живого входа.** OzonID — realm, который защищает
  оформление, — держит состояние там, куда снапшот куки не достаёт, поэтому
  браузер работает на постоянном профиле; см. [Сессия и стейт](#сессия-и-стейт).
- **Выбирать можно только сохранённые адреса.** `configure_checkout` переключает
  между пунктами из адресной книги аккаунта; добавление нового с карты не
  реализовано.
- **Адреса по отправлениям поддержаны, но не проверены живьём.** Заказ может
  разбиваться на отправления со своими адресами; этот путь закрыт конструкцией и
  юнит-тестом, а не реальным заказом с несколькими адресатами.
- **Размещение заказа тратит реальные деньги** и закрыто отдельным флагом
  `OZON_ENABLE_ORDERS`, а не общим флагом записи.
